# Модуль 4 занятие 7

RAG-ассистент отвечает по найденным фрагментам учебного корпуса ПромТеха и указывает документ и место для каждого факта. Если score недостаточен или контекст не содержит ответа, возвращается точная фраза: «В базе нет данных по этому вопросу.»

## Запуск

Из корня репозитория на macOS:

```bash
source venv/bin/activate
pip install -r module_04/requirements.txt
cd module_04
docker compose up -d
python ingestion.py
python rag_assistant.py
```

Скрипт читает `GIGACHAT_CREDENTIALS` и необязательный `GIGACHAT_SCOPE` из локального `module_04/.env` либо общего `.env` в корне. Ключ не записывается в исходники и результаты. Манифест `data/index_manifest.json` создаётся локально командой сборки индекса и исключён из Git. В резервном режиме запускайте обе команды с `--embedded`; база `qdrant_chunks/` также исключена из Git.

После старта введите `q3`, `q11`, `q12` или `q13` (можно просто номер). Для вопроса, прошедшего порог, показываются найденные чанки, score, решение gate, полный контекст, system/user сообщения и настоящий ответ GigaChat. При отказе по score генератор не вызывается.

Сравнение ответа модели без источников и ответа RAG:

```bash
python rag_assistant.py --case
```

## Выполненные функции

- `format_context` нумерует фрагменты, добавляет `doc_id` и место через готовую `where()`, сохраняет текст полностью.
- `build_prompt` задаёт ответы только по контексту, подтверждающие ссылки `[doc_id, место]` и точный отказ при недостатке данных. В user-сообщение попадают только контекст и вопрос; учебные `expected`, `must_contain`, `in_corpus` и `note` модели не передаются.
- `confidence_gate` отказывает при пустой выдаче либо лучшем score ниже 0.5. При score ровно 0.5 запрос проходит.

`ingestion.py`, `vector_store.py`, `corpus_loader.py` и `qdrant_connect.py` перенесены без изменений из завершённого модуля 3. Параметры индекса — 600/150, 28 документов, 176 записей, 921 чанк, 384 измерения, Cosine, алиас `promtech`.

## Проверка

Локальные проверки без сетевого вызова генератора:

```bash
python check_rag.py
```

Пять проверок покрывают сохранность полного текста, страницы и разделы, состав сообщений, границу порога и отсутствие вызова GigaChat при отказе. Отдельно выполнены реальные запуски обычной команды ассистента и кейса; их вывод сохранён в `results/`.

| Прогон | Что проверяется | Результат |
| --- | --- | --- |
| q3 | Периодичность проверки знаний | Факт «не реже одного раза в год», ссылка на REGL-GEN-02 |
| q11 | Столица Австралии, вне базы | Score 0.1941, точный отказ без вызова модели |
| q12 | Собственный вопрос о согласовании ремонта | Факт «главный инженер производства», ссылка на REGL-GEN-01, раздел 5.1 |
| q13 | Собственный вопрос об авторе романа | Score 0.2989, точный отказ без вызова модели |
| --case | Срок устранения критичных неисправностей | RAG называет «до 1 рабочего дня» и ссылается на REGL-GEN-01, раздел 5.1 |

Все результаты получены реальными запусками; генератор в сохранённых RAG-прогонах не подменяется. Подмена API используется только внутри локальных проверок `check_rag.py`. Точный текст ответа GigaChat может меняться между запусками.
