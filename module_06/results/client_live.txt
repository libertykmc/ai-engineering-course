MCP-ХОСТ ПромТеха: фраза → выбор tool (GigaChat) → вызов MCP
════════════════════════════════════════════════════════════════════════════════════════
Сервер: mcp_server_basic.py (подпроцесс, транспорт stdio)
Модель: GigaChat выбирает tool из каталога MCP, не из «своей памяти».

Сессия MCP открыта.

──── 1. КАТАЛОГ MCP (то, что видит хост) ──────────────────────────────────────────

  Tools (2) — действия, которые модель может выбрать:
  • get_equipment_status — Возвращает текущий статус оборудования по id; каждый исход идёт в аудит.
    schema: {"properties": {"equipment_id": {"title": "Equipment Id", "type": "string"}}, "required": ["equipment_id"], "type": "object", "title": "get_equipment_statusArguments"}
  • create_incident — Создаёт инцидент после проверок роли, оборудования и приоритета.
    schema: {"properties": {"equipment_id": {"title": "Equipment Id", "type": "string"}, "description": {"title": "Description", "type": "string"}, "priority": {"title": "Priority", "type": "string"}, "role": {"default": "viewer", "title": "Role", "type": "string"}}, "required": ["equipment_id", "description", "priority"], "type": "object", "title": "create_incidentArguments"}

  Resources (1) — данные без вызова tool:
  • equipment://list — list_equipment

────────────────────────────────────────────────────────────────────────────────────────
Дальше пишите обычной фразой. Хост (GigaChat) сам выберет tool.
Примеры:
  • какой статус у насоса PUMP-07?
  • создай инцидент по SEP-04: растёт вибрация, приоритет high
  • узнай статус CONV-09
  • зарегистрируй аварию на NO-SUCH-ID (увидишь отказ сервера)
Команды: «помощь», «каталог», «выход».
